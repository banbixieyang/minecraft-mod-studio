# 积木编程：像搭积木一样写模组逻辑

> **证据等级 `verified-26.3`**：本文描述的每条流程都在本机跑通过 ——
> 界面上搭的程序真跑 Gradle 编译过（Fabric 26.3 和 Forge 1.20.1 都过）。

不想写代码？顶栏点「**积木**」，用拖积木的方式写模组逻辑。
写出来的东西**是真 Java**，跟手写的类一样参与构建。

> **第一次用？** 顶栏「积木」→ 工具条「**❓ 入门**」，
> 界面里有个 11 步的向导，能替你一步步操作界面。
> 配套文章：[积木编程入门](08-积木编程入门.md)。

## 0. 它是什么

```
┌────────────┬────────────────────────────┬──────────────┐
│  积木库     │          画布                │   属性       │
│            │                            │              │
│ 事件 6 条   │  ┌── 当玩家右键方块时 ──┐   │ 编译预览     │

│            │  │  把积木拖到这里    │ │   │              │

三栏：

| 位置 | 干什么 |
|---|---|
| 左 · 积木库 | 按分类列出所有能用的积木。点一下加到画布，也能拖 |
| 中 · 画布 | 你的程序。每段程序从「事件帽」开始往下长 |
| 右 · 属性 | 选中积木的说明 + **实时编译预览**（改一下就能看到 Java 变什么样）|

## 1. 搭第一段程序

三步：

1. **左栏点一个事件积木**（比如「当玩家右键方块时」）→ 画布上出现一个帽子
2. **点别的分类，点一条语句积木**（比如「对玩家说」）→ 接到帽子下面
3. **在积木上直接改参数** —— 文本框里写什么，生成的 Java 就是什么

条件积木（`如果…那么`）下面有个**空槽**，把语句积木拖进去就行。
空条件位默认是「假」，点一下那个小按钮能切「真/假」。

右上角点「**编译预览**」，右边立刻显示这段程序编译出来的 Java：

```java
public static void on_player_rightclick_block(
        net.minecraft.server.level.ServerPlayer player, ...) {
    if ("聊天栏".equals("动作栏")) {
        player.sendSystemMessage(
            net.minecraft.network.chat.Component.literal("你好！"), false);
    } else {
        ...
    }
}
```

## 2. 存下来、真编译

- 顶栏「**保存**」→ 积木程序存进工程（`.studio/project.json` 的 `visual.programs`）
- 顶栏「**生成**」→ 编译成 `src/main/java/<包名>/custom/ModLogic.java`
- 顶栏「**构建 jar**」→ 真跑 Gradle

**生成区会被覆盖。** 手写代码请写到别的类里，或者把逻辑拆成多个积木程序。

## 3. 积木库：把常用功能打包

「积木库」= 一包可以到处用的积木。装上之后里面的积木出现在左栏，任何工程都能用。

### 从 mod jar 生成库（G4，任意 mod 都能转）

点顶栏「**积木库**」→「从 mod jar 生成库」，填 jar 路径：

```
C:/Users/Lenovo/Downloads/goety-2.5.55.4.jar
```

工具会读这个 jar，生成三类积木：

| 类型 | 怎么编译 | 说明 |
|---|---|---|
| 物品 / 方块 / 效果 | **只用原版注册表 API** | 装了那个 mod 的工程都能编 |
| 可调用的功能 | 扫 mod class 里的 `public static` 方法 | 标着「未验证」，先当参考 |
| mod 专属积木 | 手写的「积木级」语义 | 比如 Goety 的「施放法术」「查灵魂能量」 |

**读 jar 不会执行里面的任何代码**，只解析类结构和注册表条目。

> ⚠️ 数据型积木用 `BuiltInRegistries.ITEM.getValue(Identifier.parse(...))` 这种原版 API，
> 所以**任何**装了那个 mod 的工程都能编译，不需要特殊配置。
>
> 但行为型和专属积木直接调 mod 自己的 API（比如 `com.Polarice3.Goety.*`），
> 工程得挂上那个 mod 的 jar 才编译得过 —— 在工程的 `localDeps` 里加：
>
> ```json
> "localDeps": [{ "name": "goety", "path": "C:/Users/Lenovo/Downloads/goety-2.5.55.4.jar" }]
> ```

### 已经做好的库

本机 `~/.mcstudio/blocks/` 下现在有：

| 库 | 条数 | 说明 |
|---|---|---|
| `goety-blocks.mcblocks.json` | 135 | Goety 主库（含 9 条专属积木） |
| `goety_revelation-blocks.mcblocks.json` | 19 | Goety: Revelation |
| `goetydelight-blocks.mcblocks.json` | 32 | Goety Delight |

### 积木依赖某个 mod 的标记

专属积木带 `requiresMod` 字段，界面上打黄色角标 + 提示，
让你知道「这条得先装那个 mod」。

## 4. 代码造积木（G5）

「**任何人**都能把一段代码打包成可视化积木块」：

1. 顶栏点「**代码造积木**」
2. 填名字、id、Java 代码模板
3. 代码里用 `%参数名` 占位，参数一个个加进来

例：

```
积木名字：给玩家三颗钻石
积木 id：mymod.give_diamond
代码：player.give(net.minecraft.world.item.ItemStack.DIAMOND, 3);
```

带参数的：

```
积木名字：给玩家 %count 个 %item
代码：player.give(new net.minecraft.world.item.ItemStack(
        net.minecraft.core.registries.BuiltInRegistries.ITEM.get(
            net.minecraft.resources.Identifier.parse(%item)), %count));
参数：item（文本）、count（数字）
```

造好后这条积木出现在左栏「自定义」分类里，可以直接拖。
点「**导出积木**」能把它导成 `.mcblocks.json` 分享给别人 ——
对方装上就能用。

**参数必须和代码里的占位符一一对应**，对不上会明确报错。

## 5. 两种写法怎么配合

积木和手写代码**互不排斥**，可以混着来：

| 场景 | 建议 |
|---|---|
| 逻辑简单、想让小朋友改 | 积木 |
| 逻辑复杂、要精细控制 | 手写 Java |
| 一部分积木 + 一部分手写 | 积木程序只管逻辑，细节调 `ModLogic` 同目录的其它类 |

两边最后都在同一个 jar 里。

## 6. 常见问题

**Q：积木拖不进去 / 放不下？**
A：槽有类型。文本槽只放文本，条件槽放条件积木，语句链只放语句积木。
放错会提示「这个位置放不下」。

**Q：改了输入框，保存后值没了？**
A：不会。改完立刻写进模型，点「保存」或「编译预览」都对。
（这个坑修过一次 —— 早期版本重绘会把改动冲掉。）

**Q：为什么有条积木是灰的？**
A：那条积木在当前目标下没有实现。切到支持它的目标（Fabric 26.3 / Forge 1.20.1）看看。

**Q：条件位怎么填？**
A：默认「假」，点那个小按钮切「真/假」。
要做复杂判断，往条件位里拖一条条件积木（比如「10 < 5」）。

**Q：生成的 Java 在哪？**
A：`src/main/java/<包名>/custom/ModLogic.java`。
