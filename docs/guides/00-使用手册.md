# 使用手册：MC Studio 全功能指南

> **证据等级 `verified-26.3`**：本文描述的每条流程都在本机跑通过，
> 包括「改数值 → 真回写生效」的完整链路（TOML 覆写 + Java 覆写代码都真编译过）。

这一篇是**地图**。它告诉你这个工具有哪几条路、每条路走哪几步、坑在哪。
想直接动手做东西，看 [01-从零到出jar](01-从零到出jar.md)；
想拆别人做的 mod，看 [06-拆解别人的mod](06-拆解别人的mod.md)。

## 0. 一句话认识它

MC Studio 是一个**不写代码也能做 Minecraft 模组**的工具，
同时也是一把**拆解别人模组的手术刀**。

它做的事：

| 你想干的 | 怎么干 |
|---|---|
| 做一个新模组 | 填表单 → 生成 → 构建 jar |
| 把别人的模组拆开看 | 导入 jar → 拆解台逐项研究 → 挑有用的存进包库 |
| 改别人模组的数值 | 拆解台改值 → 导出成新包（含真正生效的覆写文件） |
| 攒一套可复用的内容 | 存进包库 → 以后一键装到任意工程 |

工具分**五个区域**，顶栏从上到下就是它们：

```
┌──────────────────────────────────────────────────┐
│ 库    分析    学习    AI    校验  代码  生成  构建 │  ← 顶栏
├──────────┬──────────────────────────┬────────────┤
│          │                          │            │
│  内容     │        编辑区             │  检查器    │
│  列表     │   （当前选中内容的表单）    │ （预览）   │
│          │                          │            │
└──────────┴──────────────────────────┴────────────┘
     ↑ 左侧栏
```

## 1. 第一次用：新建一个工程

首页只有两个选择：**新建工程** / **打开已有工程**。

### 新建工程要填三样

| 字段 | 填什么 | 注意 |
|---|---|---|
| 中文名 | 随便 | 只在界面上显示 |
| 工程 id | `lower_snake_case` | **这是命名空间**，物品会变成 `rubyworks:ruby` |
| 包名 | 反向域名 | `com.example.rubyworks` |

> ⚠️ **工程 id 一旦定下来就别改。** 所有资源路径都挂在它下面，
> 改了等于所有东西重新注册一遍。

### 目标版本

默认是 **Fabric 26.3**。也可以选 **Forge 1.20.1**（需要本机有对应 JDK）。

两条路线用的是**完全不同的 API**：

| | Fabric 26.3 | Forge 1.20.1 |
|---|---|---|
| Java | 25 | 17 |
| 物品写法 | 组件式（`Item.Properties`） | `new Item(new Item.Properties())` |
| 装备 | `equipment/*.json` 描述层 | `ArmorMaterial` 数值 |
| 创造栏事件 | `CreativeModeTabEvents` | `BuildCreativeModeTabContentsEvent` |

**别混着抄代码。** 细节见 [05-Forge-1.20.1-从零到出jar](05-Forge-1.20.1-从零到出jar.md)。

工程建在 `mcstudio/projects/` 下，生成后立刻可以构建。

## 2. 自己做内容：完整流程

```
加内容 → 校验 → 生成 → 构建 jar → 丢进 mods/
```

### 2.1 加内容

左侧栏是内容类型（物品、方块、配方、工具材质、盔甲材质、矿物生成、进度……）。
点类型 → 点「添加」→ 填表单。

**最少要填的**：id（`ruby`）和中文名（`红宝石`）。

四种物品类型各自的字段见 [02-物品与方块](02-物品与方块.md)。

### 2.2 校验

顶栏「校验」按钮。它会检查：
- id 是否合法（小写字母开头，只含小写字母/数字/下划线，2~48 字符）
- 有没有条目缺必填字段
- 代码片段是不是空的

**养成习惯：改完先校验。** 校验能在生成之前把问题拦下来。

### 2.3 生成

顶栏「生成」。这一步把表单变成**真正的 Java 代码和资源文件**：

```
src/main/java/<你的包名>/...     ← 注册物品、方块、事件监听器
src/main/resources/assets/<ns>/  ← 模型、贴图、语言文件
src/main/resources/data/<ns>/    ← 配方、战利品表、矿物生成
```

生成是**幂等**的：改了表单再生成一次，之前生成的文件会被覆盖，手写区保留。

### 2.4 构建 jar

顶栏「构建 jar」。跑 Gradle，产物在 `projects/<工程>/build/libs/`。

**前置条件**：对应版本的 JDK 必须在 `mcstudio/jdk/` 或系统里，
且版本要对（26.3 要 Java 25，1.20.1 要 Java 17）。顶栏「更多」里能看检测结果。

### 2.5 装进游戏

把 `build/libs/` 里的 jar 丢进游戏的 `mods/` 文件夹。

Fabric 26.3 还要装对应的 Fabric Loader 和 Fabric API。

## 3. 拆别人的 mod：完整流程

这是这个工具最有特色的能力。**详见 [06-拆解别人的mod](06-拆解别人的mod.md)**，
这里只给一张地图：

```
导入 jar → 分析 → 拆解台研究 → 改数值 → 导出成新包 → 装进工程
```

### 3.1 导入

顶栏「分析」→ 拖一个 jar 进去（或点选择文件）。

分析器会做三件事：

| 看什么 | 怎么看的 | 准不准 |
|---|---|---|
| 物品、方块、配方、掉落、矿物生成、进度 | 读 jar 里的 JSON 资源 | **准** —— 那就是数据本身 |
| 状态效果、法术、附魔、可调数值 | 读 class 文件的字节码常量池 | 有证据支持，带证据列出 |
| 这是个什么 mod、什么加载器、什么版本 | 读 mod 描述文件（fabric.mod.json / mods.toml） | **准** |

### 3.2 拆解台

顶栏「分析」→ 找到刚导入的 mod → 点「拆解」。

拆解台左侧是分组：

| 分组 | 内容 |
|---|---|
| 物品 / 方块 / 配方 / 矿物生成 / 进度 | 从资源还原的（准） |
| 工具材质 / 盔甲材质 | 推出来的（资源里读不到数值，默认给钻石档） |
| **代码能力** | 从字节码看出来的能力，每条带「证据」 |
| **状态效果 / 法术 / 数值配置 / 附魔** | 扩展提供的（Forge mod 的数值常在这里） |
| 源码 | 只有 sources jar 才有 |

> 💡 **分组多出来几个是正常的** —— 那说明命中了扩展。
> 扩展是「像 mod 一样拓宽引擎」的能力包，见第 6 节。

### 3.3 改数值 → 真回写生效

这是最关键的一环，也是和「只能看」的工具最大的区别。

在拆解台里改数值 → 顶栏「**预览生效产物**」→ 看到要生成什么 → 导出成包。

导出的包里会带：

| 文件 | 作用 |
|---|---|
| `config/<mod>/xxx.toml` | **配置覆写** —— 放进游戏的 config 目录即生效 |
| `src/main/java/.../XxxConfigOverrides.java` | **运行时覆写代码** —— 编译进 jar，改内存里的值，立刻见效 |
| `README.md` | 改了什么、原本是多少 |

两条路都生成，是有意的：
- **TOML** 适合「游戏启动时读配置」的场景，改了要重启游戏；
- **Java** 适合「进游戏立刻生效」的场景，不用重启。

> 🔑 **这是 Forge mod 专属的能力。** 数值写在 Forge 配置系统里的 mod
> （Goety 系列就是）才能这么改。数值写死在代码里的 mod 改不了 ——
> 那需要改源码重新编译，性质完全不同。

### 3.4 存进包库

拆解台里挑中要的 → 「存入库」。包会存到 `~/.mcstudio/packs/`。

包是**可复用**的最小单位：以后新建工程时一键装上，不用重新拆。

## 4. 包库：攒和用

顶栏「库」。

### 包是什么

一个包（`.mcpkg.json`）能装三类东西：

| 类型 | 例子 |
|---|---|
| **内容条目** | 一件物品、一个配方、一组附魔 |
| **代码片段** | 一段 Java（吸血逻辑、事件监听器） |
| **静态文件** | 配置文件、语言文件、贴图 |

### 装到工程

选包 → 「应用到当前工程」。

需要 JDK 的包（带 Java 代码的）会要求你提供**参数**（包里的 `{{参数名}}`），
填完才生成。

### 值的去留

包默认**不覆盖**你已有的同名内容 —— 除非包声明了 `createOnly: false`（覆写）。
所以「装一个包」不会把你手写的东西冲掉。

## 6. 扩展系统：让引擎加载新工具

分析器的能力可以**用扩展包扩充**，就像 Minecraft 的 mod 一样。

### 现有扩展

| 扩展 | 管什么 |
|---|---|
| `goety-base` | Goety 基础库：112 状态效果、125 法术、1579 条数值配置、18 酿造、13 附魔 |
| `goety-revelation` | 终末启示：聚晶、套装词条、仪式配方 |
| `goety-delight` | Goety Delight：33 条数值配置、18 状态效果、5 附魔、111 条仪式/料理配方 |

### 扩展怎么工作

```
core/analyze/ext/<扩展名>/index.mjs
```

每个扩展导出一个对象：

```js
export default {
  id: 'my-mod',
  name: '我的扩展',
  order: 10,                          // 越小越先跑
  match: (meta) => meta.id === 'mymod',  // 命中哪些 mod
  contentTypes: {                     // 新增的内容类型（拆解台里会多出分组）
    myEffect: { label: '我的效果', icon: '✦' },
  },
  fields: {                           // 哪些字段可编辑
    myEffect: [{ key: 'nameZh', label: '名称(中)', kind: 'text' }],
  },
  handlesRecipeTypes: ['mymod:custom'],  // 这些配方类型我接管了，别报「已跳过」
  analyze(ctx) {
    // ctx: { src, meta, mainNs, lang, contents }
    return { contents: { myEffect: [...] }, warnings: [] };
  },
  onExport(ctx) {
    // ctx: { report, selection, overrides, pack, projectModId, projectPkg }
    return { files: [], java: [], warnings: [] };
  },
};
```

### ⚠️ 改完扩展要重启服务

扩展是**服务启动时一次性装载**的（刻意对齐 MC 的 mod 语义 ——
改 mod 要重启游戏）。新增或修改扩展后，**必须重启 MC Studio 服务**才生效。

这是最容易踩的坑：改完扩展，拆解台里分组没出来，
多半就是忘了重启。

### 通用模块

`core/analyze/forge/` 下有两个与具体 mod 无关的通用模块：

| 模块 | 干什么 |
|---|---|
| `config.mjs` | 从任意 ForgeConfigSpec 配置类里提取数值条目（默认值、范围、说明、所属 toml） |
| `override.mjs` | 把改过的数值生成 TOML 覆写 + Java 覆写代码 + 说明文档 |

新扩展要支持「改数值回写」，直接复用这两个模块就行。

## 7. 常见问题

### 构建失败

| 现象 | 原因 |
|---|---|
| `Unsupported class file major version` | JDK 版本不对。26.3 要 Java 25，1.20.1 要 Java 17 |
| `找不到依赖` | Gradle 第一次构建要下依赖，需要联网 |
| `找不到 xxx 资源` | 生成没跑，或者 id 改了没重新生成 |

### 拆解结果不对

| 现象 | 原因 |
|---|---|
| 分组是空的 | jar 里没这个 mod 的资源（可能是纯代码 mod） |
| 数值改了不起作用 | 这个 mod 的数值写死在代码里，不在配置系统里 |
| 「代码能力」很少 | 发布包经过重映射，方法名不可读，只能看字符串证据 |
| 少了一堆东西 | 看警告列表，多半写了「某某类型的配方暂不支持」 |

### 通用排查

顶栏「更多」→ 有诊断信息。分析报告里的**警告列表**是最重要的线索 ——
引擎只说自己确定的事，不确定的地方会明确说出来，而不是悄悄糊过去。
