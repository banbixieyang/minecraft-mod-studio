# MC Studio 使用手册

把「做一个 Minecraft mod」拆成可视化表单 + 一键出 jar 的本地工具。
不会写 Java 也能做出带物品、方块、配方、矿物生成的 mod；会写代码的人可以在钩子里插自己的逻辑，少写一堆样板。

> **这份文档是仓库里的精简版。**
> 应用内的 **学习中心 →《使用手册：MC Studio 全功能指南》** 才是完整版（八章 + 一张速查表），
> 讲的每条路都在本机跑通过。仓库里的完整副本在 [`guides/00-使用手册.md`](./guides/00-使用手册.md)，
> 由 `tools/sync-docs.mjs` 从应用内的正本同步而来，改内容只改正本。

当前支持两个目标，新建工程时在下拉里选：

| 目标 | MC | JDK | 构建 | 备注 |
| --- | --- | --- | --- | --- |
| **Fabric 26.3** | 26.3 | 25 | Loom 1.17.21 / Gradle 9.5.1 | 组件式物品 API |
| **Forge 1.20.1** | 1.20.1 | 17 | ForgeGradle 6.x / Gradle 8.8 | 官方 MDK 47.4.0，`mods.toml` |

两个目标用同一套界面和内容表单；资源方言、Java 骨架、注册方式由目标适配器决定。
**它们需要各自的 JDK**，切换目标后首次构建会各自下载依赖。

---

## 一、启动

```bash
cd mcstudio
node studio.mjs start
```

浏览器会自动打开 `http://127.0.0.1:4173`。关掉终端窗口即停止。

只想跑一次生成、不开界面：

```bash
node studio.mjs generate projects/我的mod
```

需要 Node 18 以上，**不需要联网装依赖**（整个工具零 npm 依赖）。

## 二、界面怎么用

打开后是四栏：

```
┌──── 顶栏：工程名 / 校验 / 代码 / 生成 / 构建 jar ────┐
│ 内容类型 │ 该类型的条目列表 │ 表单          │ 实时检视 │
│ 物品 5  │ 红宝石           │ 标识符 …      │ 贴图预览 │
│ 方块 3  │ 红宝石剑         │ 中文名 …      │ 刷新预览 │
│ …       │ …                │ 贴图来源 …    │ Blockbench│
└─────────┴──────────────────┴───────────────┴──────────┘
```

- **左栏**：内容类型。数量是工程里已有的条目数。
- **第二栏**：当前类型的所有条目。`+` 新建，条目右上角有复制 / 上下移 / 删除。
- **中间**：表单。字段旁的小字是给不知道填什么的人准备的（比如耐久「钻石 1561」）。
- **右栏**：贴图预览 + 打开 Blockbench + 查看这个条目产出哪些文件。

表单里的改动会自动保存到 `.studio/project.json`，不需要点保存。

### 第一次来：首页的四张卡

首页下半部分有「第一次来？先看这几条路」，四张卡对应四条主路：

| 卡片 | 讲什么 | 点下去会去哪 |
| --- | --- | --- |
| ① 我想用积木搭 | 拖积木写逻辑，生成真 Java | **直接进积木编辑器并打开入门向导** |
| ② 我要做自己的模组 | 填表单 → 生成 → 构建 jar | 学习中心《从零到出 jar》 |
| ③ 我想拆别人的模组 | 导入 jar → 逐项研究 → 改数值 | 学习中心《拆解别人的 mod》 |
| ④ 我想要一份完整手册 | 六个区域、每个功能怎么走 | 学习中心《使用手册》 |

积木那张跟别的三张不一样：它不进学习中心，而是**直接把人送进编辑器**，
左边自动弹出 11 步的入门向导，点「带我做」还会替你在界面上操作。

顶栏还有一个 **「手册」** 按钮，任何时候点它都直达使用手册 —— 不用先找教程在哪。

### 顶栏按钮

| 按钮 | 作用 |
| --- | --- |
| 库 | 打开效果库：把做好的内容/代码打包复用，或把别人的包装进来 |
| 积木 | 打开积木编辑器：拖积木写模组逻辑，生成真 Java |
| 分析 | 把别人的 mod jar **拖进面板**直接解析，读出内容与能力，勾选后转成包；也能手填路径 / 浏览磁盘 |
| 学习 | 打开学习中心：内置指南、Fabric 26.3 与 Forge 1.20.1 速查、任务卡，能搜能跳 |
| 手册 | 直达《使用手册：MC Studio 全功能指南》 |
| AI | 打开 AI 助手：它读得到学习中心的内容，也知道这个版本的坑。回答边生成边显示，觉得不对随时按「停止」 |
| 校验 | 生成前检查：id 重复、引用了不存在的材质、配方空格不合法等，一次性列出来 |
| 代码 | 浏览生成出来的全部源码与资源，标了「生成」/「手写」 |
| 生成 | 把表单内容写成 Java + JSON + PNG |
| 构建 jar | 调 Gradle 编译，日志实时滚。成功后给出 jar 路径，可以一键部署到客户端 mods 目录 |

「库」「分析」「学习」「AI」是整屏面板，左上角「← 返回编辑」退回来。

分析面板最上面是拖放框：从网上下载的、别人发来的 jar 直接拖进去就自动分析。
文件副本放在 `~/.mcstudio/imports/`，「管理已导入…」能重新分析或删除副本。
第三方发布包的签名 / 重映射 / 内嵌 jar 会在报告里单独标出来，内嵌的能点「单独分析」拆开看。
**发布版 jar 只有 `.class`，编辑器不会假装有原作者源码**；能复用的是资源内容和可编译的效果模板。
详细的复用规则见 [`reuse-and-analysis.md`](reuse-and-analysis.md)，
知识库与 AI 的用法见 [`knowledge-and-ai.md`](knowledge-and-ai.md)。

### 不知道某个东西怎么写的时候

先按 **学习**，搜你要做的事（「注册物品」「时运」「mixin 注入」），
结果按**章节**返回，点一下就跳到那一段。代码块右边有「复制」和「问 AI」——
「问 AI」会带着这段代码和你的问题一起发过去。

再不行按 **AI**，把「你想让游戏发生什么」说清楚就行，不用说术语。
它答完会列出「依据：资料 1 / 资料 2」，点一下跳回学习中心对应那节。

## 三、搭积木写逻辑（不用写代码）

顶栏「**积木**」打开一个 Scratch 式的编辑器：

```
┌────────────┬────────────────────────────┬──────────────┐
│  积木盒     │          画布                │   右边        │
│  事件 6 条   │  ┌── 当玩家每 tick 时 ──┐   │  编译预览     │
│  玩家 9 条   │  └── 对玩家说：___ ▾ ──┐   │  （真 Java）  │
│  流程 4 条   │  ┌ 如果 [假] 那么 ───┐ │   │              │
│  ...        │  │  给玩家 5 点生命   │ │   │  工程概览     │
└────────────┴────────────────────────────┴──────────────┘
```

**生成出来的是真 Java** —— 写进 `src/main/java/<包名>/custom/ModLogic.java`，
跟手写的类一样参与 Gradle 构建。Fabric 26.3 和 Forge 1.20.1 都真编译验证过。

### 三步搭出第一段程序

1. 左栏点一个**事件**积木（「当玩家每 tick 时」）→ 画布上出现一个帽子
2. 点别的分类，点一条**语句**积木（「对玩家说」）→ 接到帽子下面
3. 在积木上的**白色小框**里改字 —— 右边的编译预览立刻变成新的 Java

条件积木（「如果…那么」）下面有个**凹槽**，把别的积木拖进去就行。
条件位默认「假」，点那个小按钮切「真 / 假」。

### 入门向导

第一次用？工具条点「**❓ 入门**」，左边弹出 11 步的向导：

- 每步都有「**带我做**」—— **向导替你在界面上操作这一步**（展开分类、真的加积木、真的填示例）
- 顶部进度点可以随便跳
- 首页那张「① 我想用积木搭」的卡会直接进编辑器并打开它

详见 [积木编程入门](./guides/08-积木编程入门.md)。

### 积木库：把常用功能打包

| 做法 | 在哪 |
| --- | --- |
| 任意 mod 的 jar → 一套积木库 | 工具条「积木库」→「从 mod jar 生成库」 |
| 一段 Java → 带参数的积木块 | 工具条「代码造积木」 |
| 导出积木分享给别人 | 工具条「导出积木」→ 存成 `.mcblocks.json` |

本机 `~/.mcstudio/blocks/` 已经装好三个 Goety 模组的库（135 + 19 + 32 = 186 条）。

详见 [积木编程](./guides/07-积木编程.md)。

## 四、从零做一个 mod

1. **启动** → 首页点「新建工程」，填名字（中文名和 id 分开填，id 只能是 `lower_snake_case`）。
2. **加材质**（可选）：如果要做一整套装备，先去「工具材质」「盔甲材质」各建一个，比如 `ruby`。
   不建也行 —— 单个工具可以直接选原版的「钻石」当底子。
3. **加物品**：类型选「材料 / 工具 / 武器 / 盔甲 / 普通物品」。
   - 选工具或盔甲时，才会出现「用哪个材质」「攻击力」这些字段（表单会跟着变）。
   - 每行说明文本会变成物品的 tooltip。
4. **加方块**：矿石 / 矿物块 / 普通方块。矿石可以配掉落物（掉什么、几个、吃不吃时运）。
5. **加配方**：3×3 网格里点格子填材料，选产出物和数量。支持有序、无序、熔炉、高炉、切石机。
6. **加矿物生成**：选维度、填矿脉大小和每区块尝试次数、Y 范围。主世界会自动分成石头层和深板岩层两套方块。
7. **点「校验」** → 没问题就 **「生成」** → **「构建 jar」**。
8. jar 在 `build/libs/<modid>-<版本>.jar`。丢进 `mods/` 就能用。

> **尺寸陷阱**：矿脉大小（size）填小于 4 时，26.3 的引擎**一个方块都不会生成**。表单里已经做了下限。

## 五、拆解别人的 mod

把一个现成的 mod jar 拖进「分析」面板，工具会读出它有哪些物品、方块、配方、
状态效果、附魔、数值配置，以及它用到了哪些能力（攻击事件、附魔、跨模组兼容…）。

拆解出来的内容可以勾选转成「包」存进效果库，之后装进自己的工程 ——
这是复用别人劳动成果最省事的路子。

**改数值想让原 mod 真的变**，有两条覆写路径（都写进 jar，放进 `mods/` 生效）：

1. **TOML 覆写** —— 目标 mod 的配置文件原样替换，适合改数值、改平衡；
2. **Java 覆写** —— 生成一段覆写代码注册进目标 mod，适合改逻辑。

完整的四步流程、覆写规则和已知边界，看 [`guides/06-拆解别人的mod.md`](./guides/06-拆解别人的mod.md)。

## 六、贴图从哪来

每个物品/方块都有「贴图来源」四选一，默认「自动」，什么都不填也有能看的图。

| 模式 | 做什么 | 适合 |
| --- | --- | --- |
| 自动 | 按物品类型挑一张原版图，按 id 里的色系词（ruby/ice/void…）自动上色 | 想立刻看到成品 |
| 原版改色 | 自己挑一张原版贴图 + 一个色板，整张重新着色 | 想控制用哪张底图 |
| 矿石合成 | 选「矿物斑点」+「宿主岩石」，逐像素差分合成矿石贴图 | 做矿石方块 |
| 自己画 | 内置 16×16 像素画板（画笔 / 橡皮 / 吸管 / 撤销） | 小改动 |

改色是**保留明暗**的：原图的亮部还是亮部，只是色相和饱和度换成目标色系，所以看起来还是原版画风。

### 和 Blockbench 配合

工具不打算替代 Blockbench。右栏「Blockbench」按钮会：

1. 把这个条目导出一份最小可用的 `.bbmodel`（含一张平面和贴图），
2. 尝试在常见安装路径找到 Blockbench 并直接打开它。

在 Blockbench 里画完，导出 PNG 覆盖到 `src/main/resources/assets/<modid>/textures/...`，
再把该条目的贴图来源切到「自己画」以外的手动模式（或直接不动，让生成器跳过这张图 —— 见下节「手写区」）。

## 七、生成区 vs 手写区

这是整个工具最重要的一条规矩。

- **生成区**：`ModItems.java`、`data/`、`assets/` 下的东西。每次「生成」都会重写。
  生成时会记录每个文件的 SHA1 指纹。**你手改过生成区文件，下次生成会报冲突而不是静默覆盖**，改回去或者点强制覆盖。
- **手写区**：`custom/CustomContent.java` 以及你自己新建的文件。**永远不会被覆盖**，只在缺失时创建一次。

要写自己的逻辑，优先用下面两种钩子，而不是直接改生成文件。

## 八、不写 Java 也能扩展：两种钩子

### 1. Java 片段钩子

生成出来的 Java 里留了锚点：

| 锚点 | 位置 | 用途 |
| --- | --- | --- |
| `// @hook:init` | 主类 `onInitialize` | 注册事件、初始化 |
| `// @hook:items` | `ModItems` 末尾 | 追加物品字段声明 |
| `// @hook:blocks` | `ModBlocks` 末尾 | 追加方块字段声明 |
| `// @hook:tabs` | `ModTabs` | 往创造栏里塞东西 |

在工程的 `hooks.java` 里写一段代码、选个锚点，每次生成都会把那一段插进去。
适合「加一个生成器还不支持的物品属性」这种补丁式需求。

### 2. JS 钩子

写一个 `.mjs`，在生成前跑，能读改工程数据、额外产出文件：

```js
export default async function (ctx) {
  ctx.log('当前物品数：' + ctx.entries('item').length);

  // 批量改：所有材料堆叠改成 16
  for (const it of ctx.entries('item')) {
    if (it.kind === 'material') it.stacksTo = 16;
  }

  // 额外产出一个文件
  ctx.addFile('src/main/resources/data/mymod/tags/item/shiny.json',
    JSON.stringify({ values: ctx.entries('item').map(i => ctx.nsId(i.id)) }, null, 2));
}
```

`ctx` 提供：`project`（整个工程数据）、`entries(type)`、`addFile(path, content)`、`log(msg)`、`nsId(短名)`。

适合「一次生成 100 个变体」「按规则算数值」这类程序化需求。

## 九、命令行

```bash
node studio.mjs start  [--port 4173] [--no-open]   打开可视化编辑器
node studio.mjs new <名字> [--id modid] [--pkg com.example.modid]
node studio.mjs generate <工程目录> [--force]       只生成，不开界面
node studio.mjs build <工程目录> [--deploy <mods目录>]  构建 jar（可顺手部署）
node studio.mjs modules                            看装了哪些模块
node studio.mjs targets                            看支持哪些平台版本
```

`start` 起的是一个普通 HTTP 服务，所有能力都有对应的 `/api/*` 接口，
所以也能接 CI、脚本、或者换个 Electron / VSCode 的壳 —— 界面和引擎是彻底分开的。

## 十、常见问题

**构建报「不支持发行版本 25」**
需要 JDK 25 的 toolchain。工程的 `build.gradle` 用 `java.toolchain` 声明了 25，
Gradle 会自动去下载（首次构建慢一点）。机器上只要有一个能跑 Gradle 的 JDK 就行。

**改了贴图又被生成覆盖了**
把该条目的贴图来源改成「原版改色 / 矿石合成 / 自己画」以外的状态会让生成器接管这张图。
长期维护的贴图建议放 `custom/` 下自己引，或者用 Java 钩子把贴图路径指向自己的文件。

**生成时提示「冲突」**
说明那个文件被手改过。生成器不会覆盖，避免吃掉你的改动。确认要放弃手改就加 `--force`。

**Forge 1.20.1 构建卡在 `gradle-8.8-bin.zip` 下载**
国内访问 Gradle 官方源常卡住。把 Gradle 8.8 发行包手动放进
`~/.gradle/wrapper/dists/gradle-8.8-bin/<hash>/`（解压出 `gradle-8.8/`，
并放一个空的 `gradle-8.8-bin.zip.ok`），wrapper 会直接用本地的。
首次构建还要反编译 Minecraft，几分钟属于正常。

**Forge 工程编译报「不支持发行版本 17」或 toolchain 找不到**
1.20.1 要 JDK 17，用 JDK 25 编会在 ForgeGradle 阶段失败。
`build.gradle` 里的 foojay 插件会尝试自动准备 JDK 17。

**Forge 工程里物品是紫黑方块 / 矿物一个都不生成**
通常是资源目录写成了 26.x 方言。1.20.1 用 `models/item/`、`recipes/`、
`tags/blocks/`、`worldgen/configured_feature/`，矿物还得有 `forge/biome_modifier/`。
编辑器会按目标自动选，手写 json 时对照学习中心的《1.20.1 踩坑清单》。

**26.3 特有的坑（工具里已经处理，手写代码时注意）**
- 不再混淆，没有 `mappings` 行，Mojang 类名直接用
- Loom 插件 id 是 `net.fabricmc.fabric-loom`（没有 `-remap` 后缀），依赖走 `implementation`
- 物品用组件式 API：`.sword() / .pickaxe() / .humanoidArmor()`
- `ItemTags.create(Identifier)` 已移除，标签统一 `TagKey.create(Registries.X, id)`
- 世界生成的实际目录是 `worldgen/feature/`，不是旧的 `configured_feature/`
- 矿脉 `size < 4` 一个方块都不生成
- 谓词键名改了：`any_of` / `all_of` 用 `rules`，`not` 用 `rule`（旧版是 `predicates` / `predicate`）

## 十一、想加东西怎么办

工具本身是三层扩展的：

- **加一种内容类型**（比如药水效果、附魔、结构）→ 写一个模块，见 [模块开发指南](./module-guide.md)。不用改引擎代码。
- **加一个游戏版本 / 加载器**（NeoForge 等）→ 照 `core/target/forge-1.20.1/` 写一个目标适配器，
  在 `core/target/registry.mjs` 里登记一行。Forge 1.20.1 就是这么加进来的：
  骨架、Java 生成、资源方言都在适配器内，引擎和内容模块不需要判断版本号。
- **让拆解台认识一个新的 mod**（比如某个 mod 有自己的一套专有配方、专有配置）→
  在 `core/analyze/ext/<名字>/index.mjs` 写一个扩展，声明它认哪种内容、怎么分析、怎么导出。
  引擎启动时自动扫描装载，**改完扩展要重启服务**才生效。
  契约（`id / name / match / contentTypes / fields / analyze / onExport`）和完整示例，
  见 [`guides/00-使用手册.md` 第六章](./guides/00-使用手册.md)。

细节都在 [模块开发指南](./module-guide.md)。
