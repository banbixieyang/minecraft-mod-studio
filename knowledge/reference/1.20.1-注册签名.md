# 1.20.1 注册签名速查（Forge）

> **证据等级 `verified-forge-1.20.1`**：签名依据官方 MDK `1.20.1-47.4.0`，
> MC Studio 生成的 Forge 骨架与两张任务卡由 `tests/forge.mjs --build` 用 Gradle 真编译通过，
> 关键字段还用 `javap` 从官方映射 jar 复核过。适用 **Forge 1.20.1 / Java 17**，
> 不要拿去用在 26.3 —— 那是另一套 API。

## 主类与两条总线

```java
@Mod(MyMod.MOD_ID)
public class MyMod {
    public static final String MOD_ID = "mymod";

    public MyMod(FMLJavaModLoadingContext context) {
        IEventBus bus = context.getModEventBus();   // mod bus：加载期
        ModItems.register(bus);                    // DeferredRegister 必须挂这里
        ModBlocks.register(bus);
        ModTabs.register(bus);
        MinecraftForge.EVENT_BUS.register(this);    // game bus：运行时事件
    }

    public static ResourceLocation id(String path) {
        return new ResourceLocation(MOD_ID, path);
    }
}
```

- `net.minecraftforge.fml.common.Mod` 用单参 `@Mod("mymod")`，没有 `@Mod.EventHandler` 那套生命周期。
- 构造器可以接收 `FMLJavaModLoadingContext`，Forge 会注入；也常见无参构造 + `FMLJavaModLoadingContext.get().getModEventBus()`。
- **挂错总线不报错，但完全不生效**：注册 / `GatherDataEvent` / `BuildCreativeModeTabContentsEvent` 挂 mod bus；
  `ServerStartingEvent` / `LivingHurtEvent` / `RegisterCommandsEvent` 挂 `MinecraftForge.EVENT_BUS`。

## 命名空间 id

`ResourceLocation` 的构造器是 public，直接 new：

```java
new net.minecraft.resources.ResourceLocation("mymod", "ruby")   // mymod:ruby
```

26.3 的 `Identifier.fromNamespaceAndPath(...)` 在 1.20.1 **不存在**。

> Forge 1.20.1 把双参构造器标成了「过时且待删除」，编译时会有一条 deprecation 警告，
> 但能正常用，官方 MDK 也是这么写的。别为了消警告改成 1.21 的
> `ResourceLocation.fromNamespaceAndPath(...)` —— 那个在 1.20.1 里根本没有。

## 物品注册

```java
public static final DeferredRegister<Item> ITEMS =
        DeferredRegister.create(ForgeRegistries.ITEMS, MyMod.MOD_ID);

public static final RegistryObject<Item> RUBY =
        ITEMS.register("ruby", () -> new Item(new Item.Properties().rarity(Rarity.RARE)));

public static void register(IEventBus bus) {
    ITEMS.register(bus);   // 少了这句，静态字段只是登记，注册不会发生
}
```

`Item.Properties` 常用链：`stacksTo(int)`、`rarity(Rarity.X)`、`fireResistant()`、`durability(int)`。
**没有** `setId()` —— 注册名由 `DeferredRegister` 负责。

取注册好的物品：`RegistryObject.get()` / `isPresent()` / `getId()`。
按 id 反查：`ForgeRegistries.ITEMS.getValue(new ResourceLocation("mymod","ruby"))`。

## 工具与自定义 Tier

1.20.1 是类继承式物品，工具类的构造器参数顺序固定：

```java
ITEMS.register("ruby_sword", () -> new SwordItem(ModTiers.RUBY, 3, -2.4F, new Item.Properties()));
ITEMS.register("ruby_pickaxe", () -> new PickaxeItem(Tiers.DIAMOND, 1, -2.8F, new Item.Properties()));
ITEMS.register("ruby_axe", () -> new AxeItem(Tiers.DIAMOND, 6.0F, -3.2F, new Item.Properties()));
```

> `SwordItem` / `PickaxeItem` / `ShovelItem` / `HoeItem` 的伤害参数是 `int`，**`AxeItem` 是 `float`**。
> 写错类型 javac 会直接报错。攻速参数是 `float`。

`Tiers` 是枚举，不能扩展，且 **没有 `COPPER`**（1.20.1 还没有铜质工具）。
自定义材质实现接口：

```java
public static final Tier RUBY = new Tier() {
    @Override public int getUses() { return 1561; }
    @Override public float getSpeed() { return 8.0F; }
    @Override public float getAttackDamageBonus() { return 3.0F; }
    @Override public int getLevel() { return 3; }
    @Override public int getEnchantmentValue() { return 10; }
    @Override public Ingredient getRepairIngredient() {
        return Ingredient.of(ModTags.RUBY_TOOL_MATERIALS);
    }
    @Override public TagKey<Block> getTag() {
        return BlockTags.NEEDS_DIAMOND_TOOL;
    }
};
```

> **这里最容易抄错**：1.20.1 的 `Tier` 只有 `default getTag()`，返回「需要什么等级工具」
> 的标签 `BlockTags.NEEDS_STONE_TOOL / NEEDS_IRON_TOOL / NEEDS_DIAMOND_TOOL`。
> `getIncorrectBlocksForDrops()` 和 `INCORRECT_FOR_*_TOOL` 是 1.20.5 起才改的名字（26.3 用后者），
> 写进 1.20.1 工程 javac 会报「方法不会覆盖或实现超类型的方法」+「找不到符号 INCORRECT_FOR_DIAMOND_TOOL」。
> 这几个字段名是用 `javap` 从本机 1.20.1 官方映射 jar 里查出来的，不是凭印象。

## 盔甲与自定义 ArmorMaterial

```java
ITEMS.register("ruby_helmet", () -> new ArmorItem(
        ModArmorMaterials.RUBY, ArmorItem.Type.HELMET, new Item.Properties()));
```

`ArmorItem.Type` 是 `HELMET / CHESTPLATE / LEGGINGS / BOOTS`（不是 26.3 的 `ArmorType`）。

`ArmorMaterial` 在 1.20.1 是接口：

```java
public static final ArmorMaterial RUBY = new ArmorMaterial() {
    @Override public int getDurabilityForType(ArmorItem.Type type) { /* 按部位返回 */ return 33 * 11; }
    @Override public int getDefenseForType(ArmorItem.Type type) { return 3; }
    @Override public int getEnchantmentValue() { return 10; }
    @Override public SoundEvent getEquipSound() { return SoundEvents.ARMOR_EQUIP_DIAMOND; }
    @Override public Ingredient getRepairIngredient() { return Ingredient.of(ModTags.RUBY_ARMOR_MATERIALS); }
    @Override public String getName() { return "ruby"; }
    @Override public float getToughness() { return 2.0F; }
    @Override public float getKnockbackResistance() { return 0.0F; }
};
```

`getName()` 决定贴图文件名：`assets/minecraft/textures/models/armor/ruby_layer_1.png` 和 `_layer_2.png`。

## 方块注册

```java
public static final DeferredRegister<Block> BLOCKS =
        DeferredRegister.create(ForgeRegistries.BLOCKS, MyMod.MOD_ID);
public static final DeferredRegister<Item> BLOCK_ITEMS =
        DeferredRegister.create(ForgeRegistries.ITEMS, MyMod.MOD_ID);

private static <T extends Block> RegistryObject<T> block(String name, Supplier<T> factory) {
    RegistryObject<T> holder = BLOCKS.register(name, factory);
    BLOCK_ITEMS.register(name, () -> new BlockItem(holder.get(), new Item.Properties()));
    return holder;
}
```

方块**必须**另外注册 `BlockItem` 才能拿到手上，1.20.1 不会自动给你。
方块属性：`BlockBehaviour.Properties.of().mapColor(MapColor.STONE).strength(3.0F, 3.0F).requiresCorrectToolForDrops().sound(SoundType.STONE)`。

## 标签

```java
public static final TagKey<Item> RUBY_TOOL_MATERIALS =
        TagKey.create(Registries.ITEM, new ResourceLocation(MyMod.MOD_ID, "ruby_tool_materials"));
public static final TagKey<Block> ORES =
        TagKey.create(Registries.BLOCK, new ResourceLocation(MyMod.MOD_ID, "ores"));
```

json 放在 `data/mymod/tags/items/*.json`（注意复数 `items`）和 `data/mymod/tags/blocks/*.json`。

## 创造栏：BuildCreativeModeTabContentsEvent

往**原版**创造栏加东西用这个 mod bus 事件，不必自己注册 `CreativeModeTab`：

```java
public static void register(IEventBus bus) {
    bus.addListener(ModTabs::addCreative);
}

private static void addCreative(BuildCreativeModeTabContentsEvent event) {
    if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
        for (RegistryObject<Item> entry : ModItems.ITEMS.getEntries()) {
            event.accept(entry);
        }
    }
}
```

`event.getTabKey()` 判栏位，`event.accept(RegistryObject<Item>)` 添加。
没有 `FabricItemGroupEvents`，也没有 26.3 的 tab builder。

## 运行时事件

```java
MinecraftForge.EVENT_BUS.register(new Object() {
    @net.minecraftforge.eventbus.api.SubscribeEvent
    public void onDeath(net.minecraftforge.event.entity.living.LivingDeathEvent event) {
        // event.getEntity() → LivingEntity；event.getSource() → DamageSource
    }
});
```

`@SubscribeEvent` 的全限定名是 `net.minecraftforge.eventbus.api.SubscribeEvent`。
用 `@Mod.EventBusSubscriber(modid = ..., bus = Mod.EventBusSubscriber.Bus.FORGE)` 可以省掉手动 register，
但那需要单独写一个类 —— 在钩子（方法体语句）里用匿名对象更合适。

常用事件与取法：

| 事件 | 关键方法 |
|---|---|
| `RegisterCommandsEvent` | `getDispatcher()` → `CommandDispatcher<CommandSourceStack>` |
| `entity.living.LivingHurtEvent` | `getEntity()` / `getSource()` / `getAmount()` / `setAmount(float)` |
| `entity.living.LivingDeathEvent` | `getEntity()` / `getSource()` |
| `entity.player.PlayerEvent.PlayerLoggedInEvent` | `getEntity()` → `Player` |
| `ServerStartingEvent` | `getServer()` → `MinecraftServer` |
