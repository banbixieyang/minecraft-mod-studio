# 1.20.1 踩坑清单（Forge）

> 这一篇专治「代码编译过了，进游戏却什么都没有」。
> 1.20.1 和 26.x 的资源目录名差得很杂，抄错一个复数就静默失效，游戏不报错。

## 1. 资源方言对照表（最容易错）

| 内容 | Forge 1.20.1 | Fabric 26.x |
|---|---|---|
| 物品模型 | `assets/<ns>/models/item/<id>.json`（`parent` 写法） | `assets/<ns>/items/<id>.json`（模型定义） |
| 装备模型 | 无独立 `equipment/*.json` | `textures/entity/equipment/...` + equipment asset |
| 配方 | `data/<ns>/recipes/` | `data/<ns>/recipe/` |
| 配方结果 | `"result": {"item":"<ns>:<id>","count":1}` | `"result": {"id":"<ns>:<id>","count":1}` |
| 熔炼结果 | `"result": "<ns>:<id>"`（字符串） | 对象 |
| 战利品表 | `data/<ns>/loot_tables/blocks/` | `data/<ns>/loot_table/blocks/` |
| 战利品函数 | `"functions": [{"function":"minecraft:apply_bonus", ...}]` | `"modifier"` 键 |
| 方块标签 | `data/<ns>/tags/blocks/` | `data/<ns>/tags/block/` |
| 物品标签 | `data/<ns>/tags/items/` | `data/<ns>/tags/item/` |
| 矿物特征 | `worldgen/configured_feature/` | `worldgen/feature/` |
| 挂到生物群系 | `data/<ns>/forge/biome_modifier/<id>.json` | 26.x 的另一种挂法 |
| 矿物 state | `{"Name":"<ns>:<id>"}` 对象 | 字符串 |
| pack_format | **15** | 26.x 的值 |
| 元信息 | `META-INF/mods.toml` | `fabric.mod.json` |

MC Studio 按工程 `target` 自动选方言，不用手改；但手写 json 时照这张表核对。

## 2. 矿物生成：光有 configured_feature 不够

1.20.1 的 `configured_feature` 必须通过 biome modifier 挂到生物群系：

```json
{
  "type": "forge:add_features",
  "biomes": "#minecraft:is_overworld",
  "features": "mymod:ruby_ore",
  "step": "underground_ores"
}
```

少了这个文件，矿物一个都不会生成，且**没有任何报错**。
另外 `state` 必须是对象：

```json
"state": { "Name": "mymod:ruby_ore", "Properties": {} }
```

写成 `"state": "mymod:ruby_ore"` 是 26.x 的写法，1.20.1 加载时会解析失败。

## 3. 工具材质：Tiers 没有 COPPER

1.20.1 的 `Tiers` 枚举只有 `WOOD / STONE / IRON / DIAMOND / GOLD / NETHERITE`。
表单里选「铜」时编辑器会落到 `IRON`，手写代码不要出现 `Tiers.COPPER`。

## 4. AxeItem 的伤害参数是 float

```java
new AxeItem(Tiers.DIAMOND, 6.0F, -3.2F, props)   // ✓
new SwordItem(Tiers.DIAMOND, 3, -2.4F, props)    // ✓ 其余工具是 int
```

写 `new AxeItem(..., 6, ...)` javac 会报构造器不匹配。

## 5. Item.Properties 没有 setId()

`setId(ResourceKey<Item>)` 是 26.3 才有的要求。1.20.1 的注册名由
`DeferredRegister.register(name, ...)` 提供。看到 `setId` 就知道抄错版本了。

## 6. 静态字段不会自己注册

```java
public static void register(IEventBus bus) {
    ITEMS.register(bus);       // 主类里必须调用
}
```

忘了这一步：不报错、不崩溃，进游戏物品压根不存在。这是 Forge 新手最常踩的一坑。

## 7. 两条总线别挂反

| 挂哪 | 事件 |
|---|---|
| **mod bus**（`context.getModEventBus()`） | `DeferredRegister`、`BuildCreativeModeTabContentsEvent`、`GatherDataEvent`、注册事件 |
| **game bus**（`MinecraftForge.EVENT_BUS`） | `RegisterCommandsEvent`、`LivingHurtEvent`、`LivingDeathEvent`、`ServerStartingEvent`、tick |

挂反同样不报错，只是永远不触发。

## 8. 方块必须有 BlockItem

只注册 `Block` 没有 `BlockItem`，方块在世界上存在但创造栏拿不到、也放不上手。
MC Studio 的 `ModBlocks` 会为每个方块顺带注册一个同名 `BlockItem`。

## 9. 盔甲贴图路径与原版命名空间

`ArmorMaterial.getName()` 返回 `"ruby"`，游戏就去找：

```
assets/minecraft/textures/models/armor/ruby_layer_1.png
assets/minecraft/textures/models/armor/ruby_layer_2.png
```

注意是 **`assets/minecraft/`**，不是 `assets/mymod/`。放错地方穿上是紫黑缺贴图。
26.3 的 `textures/entity/equipment/` 在 1.20.1 不存在。

## 10. 战利品表：functions 不是 modifier

```json
{
  "type": "minecraft:block",
  "pools": [{
    "rolls": 1,
    "entries": [{
      "type": "minecraft:item",
      "name": "mymod:ruby",
      "functions": [{ "function": "minecraft:apply_bonus", "enchantment": "minecraft:fortune", "formula": "minecraft:ore_drops" }]
    }]
  }]
}
```

1.20.1 用 `functions` 数组 + `function` 声明类型。26.x 改成 `modifier` 单键，
而且 26.x 的精准采集条件在 1.20.1 里也不存在，别照抄。

## 11. mods.toml 的 modId 必须和工程 id 一致

`[[mods]] modId`、`[[dependencies.<modId>]]` 的段名、主类 `MOD_ID` 三处要一致且全小写。
不一致时启动报「依赖不满足」或直接不加载。版本范围：forge `[47,)`、minecraft `[1.20.1,1.21)`。

## 12. Java 17 与 Gradle 8.8

- toolchain 17，用 JDK 25 编会在 ForgeGradle 阶段失败
- ForgeGradle `[6.0,6.2)`、Gradle 8.8
- 映射是 `official` / `1.20.1`，别写 1.20.2 的映射版本
- `jar` 必须 `finalizedBy 'reobfJar'`：dev 用 mojmap，运行时混淆名，少了会 `NoClassDefFoundError`

## 13. 首次构建慢不是坏了

ForgeGradle 首次要下载 Forge、Minecraft、反编译产物。卡在 Gradle 发行包下载时，
手动把 8.8 发行包放进 `~/.gradle/wrapper/dists/gradle-8.8-bin/<hash>/` 即可（见入门指南第 2 节）。

## 14. `spawnAtLocation` 在 1.20.1 还在

```java
event.getEntity().spawnAtLocation(new ItemStack(item));
```

26.3 移除了这个方法、改用 `entity.drop(...)`。反过来，在 1.20.1 用 `drop(...)` 也编不过。
任务卡里的 Forge 代码都用 `spawnAtLocation`。

## 15. 钩子代码不能有 import

Java 钩子插进方法体，写 `import` / `package` / 类声明一定编不过。
代码块按钮「装成钩子」会做静态检查拦下这些写法，一律用全限定名：

```java
net.minecraft.world.item.ItemStack stack = new net.minecraft.world.item.ItemStack(net.minecraft.world.item.Items.DIAMOND);
```

## 16. 工具材质：1.20.1 是 getTag() + NEEDS_*_TOOL

这是最容易从 26.3 资料抄错的一处。1.20.1 的 `Tier` 接口（本机 `javap` 核实）只有：

```java
public default TagKey<Block> getTag();
```

等级标签是 `BlockTags.NEEDS_STONE_TOOL / NEEDS_IRON_TOOL / NEEDS_DIAMOND_TOOL`。
`Tier.getIncorrectBlocksForDrops()` 和 `BlockTags.INCORRECT_FOR_*_TOOL` 是 **1.20.5 起**改的名字，
26.3 用后者。写进 1.20.1 会得到两条错误：

```
错误: 方法不会覆盖或实现超类型的方法
错误: 找不到符号  INCORRECT_FOR_DIAMOND_TOOL
```

MC Studio 的 Forge 生成器已经按 `getTag()` 输出，并把表单里的工具等级映射到对应的 `NEEDS_*_TOOL`。

## 17. `new ResourceLocation(String, String)` 会有过时警告

1.20.1 Forge 把双参构造器标成待删除，javac 会打印 3 条 `[removal]` 警告。
**警告不影响编译**，官方 MDK 也这么写。不要改成 1.21 的 `ResourceLocation.fromNamespaceAndPath(...)`。
