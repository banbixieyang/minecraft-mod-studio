# 26.3 事件与命令速查

Fabric 没有全局事件总线。事件是各模块的静态字段，`.register(...)` 挂回调，多个监听者都会执行（不会互相顶掉）。

回调都是函数式接口，可以直接写 lambda。

## 生命周期

```java
// 服务端正在启动（此时还不能放玩家进来）
net.fabricmc.fabric.api.event.lifecycle.v1.ServerLifecycleEvents.SERVER_STARTING
        .register(server -> { });

// 启动完成
net.fabricmc.fabric.api.event.lifecycle.v1.ServerLifecycleEvents.SERVER_STARTED
        .register(server -> { });

// 每个维度加载
net.fabricmc.fabric.api.event.lifecycle.v1.ServerWorldEvents.LOAD
        .register((server, world) -> { });

// 每 tick（20 次/秒）
net.fabricmc.fabric.api.event.lifecycle.v1.ServerTickEvents.END_SERVER_TICK
        .register(server -> { });
```

`ServerTickEvents` 还有 `START_SERVER_TICK`（tick 开始）和 `END_WORLD_TICK`（每个维度结束时）。

## 实体与战斗

```java
// 允许/拒绝受伤。返回 false = 取消这次伤害
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.ALLOW_DAMAGE
        .register((entity, source, amount) -> true);

// 受伤之后（已经扣完血）
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.AFTER_DAMAGE
        .register((entity, source, base, taken, blocked) -> { });

// 死亡之后
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.AFTER_DEATH
        .register((entity, source) -> { });

// 允许/拒绝死亡（返回 false 就死不了）
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.ALLOW_DEATH
        .register((entity, source, amount) -> true);
```

`AFTER_DAMAGE` 的五个参数容易记混，顺序是：`entity`（挨打的）、`source`（伤害来源）、`base`（原始伤害）、`taken`（实际扣的）、`blocked`（被挡掉的）。

## 玩家交互

```java
// 右键物品
net.fabricmc.fabric.api.event.player.UseItemCallback.EVENT
        .register((player, world, hand) -> net.minecraft.world.InteractionResult.PASS);

// 右键方块
net.fabricmc.fabric.api.event.player.UseBlockCallback.EVENT
        .register((player, world, hand, hit) -> net.minecraft.world.InteractionResult.PASS);

// 左键方块（开始挖）
net.fabricmc.fabric.api.event.player.AttackBlockCallback.EVENT
        .register((player, world, hand, pos, direction) -> net.minecraft.world.InteractionResult.PASS);

// 方块被破坏之后
net.fabricmc.fabric.api.event.player.PlayerBlockBreakEvents.AFTER
        .register((world, player, pos, state, entity) -> { });
```

**返回 `PASS` = 不处理，交给原版。返回 `SUCCESS` = 你处理了，原版不再管。**
写错这个，最常见的结果是「右键能触发，但物品也用掉了」或者反过来的「右键没反应」。

服务端判断：`if (world.isClientSide()) return InteractionResult.PASS;`

## 连接

```java
net.fabricmc.fabric.api.networking.v1.ServerPlayConnectionEvents.JOIN
        .register((handler, sender, server) -> {
            net.minecraft.server.level.ServerPlayer player = handler.getPlayer();
        });

net.fabricmc.fabric.api.networking.v1.ServerPlayConnectionEvents.DISCONNECT
        .register((handler, server) -> { });
```

## 命令

```java
net.fabricmc.fabric.api.command.v2.CommandRegistrationCallback.EVENT
        .register((dispatcher, registryAccess, environment) -> {
            dispatcher.register(
                    net.minecraft.commands.Commands.literal("hello")
                            .executes(ctx -> {
                                ctx.getSource().sendSuccess(
                                        () -> net.minecraft.network.chat.Component.literal("你好"), false);
                                return 1;
                            }));
        });
```

要点：

- 回调三个参数是 `CommandDispatcher<CommandSourceStack>`、`CommandBuildContext`、`Commands.CommandSelection`。
- `sendSuccess` 第一个参数是 `Supplier<Component>` —— 要包一层 lambda，不能直接传 `Component`。
- 返回值用 `1`（= `Command.SINGLE_SUCCESS`）。

带参数：

```java
dispatcher.register(
        net.minecraft.commands.Commands.literal("giveitem")
                .requires(source -> source.hasPermission(2))
                .then(net.minecraft.commands.Commands.argument("item",
                                net.minecraft.commands.arguments.ItemArgument.item(registryAccess))
                        .executes(ctx -> {
                            net.minecraft.world.item.ItemStack stack =
                                    net.minecraft.commands.arguments.ItemArgument.getItem(ctx, "item");
                            ctx.getSource().getPlayerOrException().getInventory().add(stack);
                            return 1;
                        })));
```

参数类型的构造一般要传 `registryAccess`（回调第二个参数），这是数据包兼容的关键。如果你看到某个参数类构造不出来，先看它的 javadoc 要什么。

## 事件注册放哪

一律放主类的 `onInitialize()`（编辑器里就是 `init` 锚点）。

放错位置最典型的症状：**单机正常，服务器不触发** —— 因为客户端侧的注册不会在专用服务端上跑。
