# 26.3 踩坑清单

按「你看到什么」查。每条都是真撞过的，不是从文档抄的。

## 1. 运行时 NPE：`Item id not set`

**现象**：游戏启动崩溃，堆栈里有 `NullPointerException: Item id not set`。

**原因**：1.21.2 起，物品的注册 key 必须写进 `Item.Properties`。老写法只传 key 给 `Registry.register` 不够。

**修法**：

```java
ResourceKey<Item> key = ResourceKey.create(Registries.ITEM, MyMod.id("ruby"));
new Item(new Item.Properties().setId(key));   // ← setId 不能漏
Registry.register(BuiltInRegistries.ITEM, key, item);
```

## 2. 编译报「找不到符号: ToolMaterial」

**现象**：`ModItems.java` 里 `ToolMaterial.DIAMOND` 报错，但类明明存在。

**原因**：import 没加。生成器曾经按「有自定义材质才 import」来判断，结果走原版材质分支的物品用了符号却没 import。

**修法**：手写代码时把 `import net.minecraft.world.item.ToolMaterial;` 加上。用编辑器生成的代码不会有这个问题（import 判定已经改成从生成的代码里反读）。

## 3. 盔甲能拿到，但穿不上

**现象**：物品栏里能看到盔甲，右键没反应，也不能穿。

**原因**：`armorMaterial` 是空的，物品退化成 `stacksTo(1)` 的普通物品。

**修法**：去「盔甲材质」标签建一个材质，回到盔甲物品上选中它。校验也会提示这一条。

## 4. 材质 id 用了 `void` / `world` / `int` 这类词

**现象**：保存时报「`void` 是保留字，请换一个」。

**原因**：条目的 id 会被用来拼 Java 常量名和类名，撞 Java 关键字或 MC 保留名就没法生成。

**修法**：加个后缀，例如 `void` → `void_mat`。分析别人 mod 时编辑器会自动做这个改写。

## 5. 矿脉写成 `size: 2`，游戏里一个都没有

**现象**：`placed_feature` 存在，`/locate` 找不到，挖到 Y 范围内也空的。

**原因**：26.3 的生成器在矿脉太小时直接跳过。**`size` 小于 4 等于不生成。**

**修法**：`size` 至少 4，正常填 6~9。

## 6. 服务端拒绝加载数据包：`Visible advancement roots must have background`

**现象**：进游戏提示数据包加载失败，日志里是这句。

**原因**：可见的**根**进度必须有背景图。

**修法**：给根进度的 `display.background` 填一张贴图（原版常用 `minecraft:textures/gui/advancements/backgrounds/stone.png`）。非根进度不需要。

## 7. `LivingEntity.spawnAtLocation(...)` 找不到方法

**现象**：编译不过，`spawnAtLocation` 不存在。

**原因**：26.3 移除了这个方法。

**修法**：

```java
entity.drop(new net.minecraft.world.item.ItemStack(item, 1),
        false,                                        // 是否打散
        net.minecraft.util.Prediction.SERVER_ONLY);   // 只在服务端发生
```

`Prediction` 是枚举，值是 `PREDICTED` / `SERVER_ONLY`。

## 8. `BuiltInRegistries.ITEM.get(id)` 不是 Item

**现象**：`Item item = BuiltInRegistries.ITEM.get(...)` 编译不过，提示类型是 `Optional<Reference<Item>>`。

**原因**：26.3 起 `get` 返回 Optional。

**修法**：

```java
var holder = net.minecraft.core.registries.BuiltInRegistries.ITEM.get(MyMod.id("ruby"));
if (holder.isEmpty()) return;
Item item = holder.get().value();
```

## 9. `ItemTags.create(...)` 不存在

**现象**：编译不过，找不到 `ItemTags.create`。

**原因**：这个方法早就没了。

**修法**：`TagKey.create(Registries.ITEM, MyMod.id("xxx"))`。方块用 `Registries.BLOCK`。

## 10. Mixin 启动就崩 `InjectionError`

**现象**：日志里 `Critical injection failure`，游戏起不来。

**原因**：注入点没命中。`injectors.defaultRequire = 1` 意味着每个注入点必须命中一次。

**修法**，按概率排序：

1. **方法名写的是 Yarn 名不是官方名** —— 26.1 起不再混淆，要用 `tick` 不是 `method_5773`。
2. `@At` 的 `target` 描述符写错（重载方法必须用完整描述符）。
3. 目标类在服务端不存在，但 mixin 写进了 `mixins` 而不是 `server` 数组。

调试时加 `-Dmixin.debug.verbose=true`，日志会打印每个注入点的匹配情况。

## 11. Mixin 配置里的 `compatibilityLevel` 填错

**现象**：启动报 `Unsupported class file major version` 或 mixin 直接不生效。

**修法**：26.3 填 `JAVA_25`。另外 **`refmap` 字段不要写** —— 新 loom 不再生成它，写了反而可能报找不到文件。

## 12. 静态字段的物品没注册上

**现象**：代码里明明有 `public static final Item RUBY = ...`，但游戏里没有。

**原因**：Java 的静态字段在类被**主动使用**时才初始化。主类没引用 `ModItems`，这个类就从来没被加载过。

**修法**：在 `onInitialize()` 里调一次 `ModItems.init();`（哪怕方法是空的）。编辑器生成的代码已经有这一行。

## 13. `IllegalStateException: This registry can't create intrusive holders`

**现象**：运行时崩，提示注册表已冻结。

**原因**：注册发生在启动完成之后（例如第一次收到某个事件时）。

**修法**：注册一律放 `onInitialize()` 调用链里。运行时要加东西用 `Registry` 之外的手段，不能重新注册。

## 14. 26.3 查不到官方文档

**现象**：`docs.fabricmc.net` 上带 `/26.3/` 的路径全是 404。

**原因**：官方文档站目前没有 26.2 / 26.3 的版本页，最新是 `/26.1.2/`。

**修法**：以**实际 jar 的类为准**。看签名用：

```bash
javap -classpath "<26.3 客户端 jar>" net.minecraft.world.item.ItemStack
```

或者在 IDE 里 Ctrl+点击看反编译。这条比任何文档都可靠 —— 本项目的 26.3 签名就是这么确认的。

## 15. 物品冷却：`addCooldown(Item, int)` 找不到方法

**现象**：`sp.getCooldowns().addCooldown(stack.getItem(), 100)` 编译不过，提示没有匹配的方法，或者「Item 无法转换为 ItemStack」。

**原因**：26.3 的 `ItemCooldowns` 收的是 **`ItemStack`**，不是 `Item`。

**修法**：

```java
sp.getCooldowns().isOnCooldown(stack)          // 传 ItemStack
sp.getCooldowns().addCooldown(stack, 100)      // 传 ItemStack
```

这类「参数从 Item 变成 ItemStack」的改动在 26.x 有一批。写之前不确定就 `javap` 看一眼。

## 16. 改完代码进游戏没变化

**顺序**：改表单 → **生成** → **构建 jar** → 重启游戏。

三个步骤任何一步漏掉都看不到变化。生成只写源码，构建才出 jar，重启才加载新 jar。

## 17. 状态效果：`MobEffects.DIG_SPEED` 找不到符号

**现象**：写 `MobEffects.DIG_SPEED` / `MOVEMENT_SPEED` / `DAMAGE_BOOST` / `MOVEMENT_SLOWDOWN`，编译报「找不到符号」，但 `MobEffectInstance` 和 `MobEffects` 本身都没报错。

**原因**：26.3 的 `MobEffects` 字段用**经典名**，老教程里的那几个描述式名字都不存在。

**修法**：常用对照（左边是 26.3 正确名）：

| 效果 | 26.3 字段名 | 别写成 |
| --- | --- | --- |
| 速度 | `SPEED` | `MOVEMENT_SPEED` |
| 缓慢 | `SLOWNESS` | `MOVEMENT_SLOWDOWN` |
| 急迫 | `HASTE` | `DIG_SPEED` |
| 挖掘疲劳 | `MINING_FATIGUE` | — |
| 力量 | `STRENGTH` | `DAMAGE_BOOST` |
| 生命恢复 | `REGENERATION` | — |
| 抗性 | `RESISTANCE` | — |

字段类型是 `Holder<MobEffect>`，直接传给 `MobEffectInstance` 构造即可，不用 `.value()`。
不确定的字段一律 `javap -classpath <minecraft-merged.jar> net.minecraft.world.effect.MobEffects` 查，别凭记忆。
映射后的 jar 在工程 `.gradle/loom-cache/minecraftMaven/net/minecraft/.../26.3/` 下。
