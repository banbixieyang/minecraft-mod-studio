# 事件与钩子：让东西有行为

表单能做的只有「注册 + 数据」。只要涉及「什么时候发生什么」，就得写代码。

## 代码写在哪：四个位置

| 位置 | 适合放什么 | 会被覆盖吗 |
|---|---|---|
| Java 钩子（选锚点） | 短逻辑：一次事件注册、几行判断 | 不会，单独存着重新插入 |
| `custom/CustomContent.java` | 长逻辑、多个方法、自己新建的类 | **永远不会** |
| `custom/` 下自己建的类 | 任何规模的东西 | 不会 |
| Mixin | 要改原版行为本身（原版没提供事件的地方） | 不会，但配置要手写 |

**建议**：先试钩子，钩子放不下就写 `CustomContent`，只有「原版不给事件」时才上 Mixin。

## 钩子的四个锚点

| 锚点 | 插到哪 | 什么时候用 |
|---|---|---|
| `init` | 主类 `onInitialize()` 里 | **绝大多数事件注册都用它** |
| `items` | `ModItems.java` 类体内（字段之后） | 要往注册表里追加物品字段 |
| `blocks` | `ModBlocks.java` 类体内 | 同上，方块 |
| `tabs` | `ModTabs.java` 里 | 往创造栏塞东西 |

钩子里的代码会被缩进后原样插到锚点那一行前面。所以**写的是「语句」，不是「方法」** —— 别写 `public void foo() {}`。

## 最重要的一条规则：用全限定名

钩子代码是插进已有方法体里的，**没有 import 可加**。写短名会直接编译失败。

```java
// ✗ 编不过：ItemStack 找不到
ItemStack stack = new ItemStack(...);

// ✓ 用全限定名
net.minecraft.world.item.ItemStack stack = new net.minecraft.world.item.ItemStack(...);
```

这条规则也适用于你自己新建的类里那些「只在一处用一次」的 API —— 用全限定名能省掉一堆 import。

## 事件速查

Fabric 的事件都是「静态字段 + register」。下面是几个最常用的，都是实测能编译的写法：

### 每 tick 执行

```java
net.fabricmc.fabric.api.event.lifecycle.v1.ServerTickEvents.END_SERVER_TICK.register(server -> {
    for (net.minecraft.server.level.ServerPlayer player : server.getPlayerList().getPlayers()) {
        // 每 tick 对每个在线玩家做点什么
    }
});
```

> 每 tick = 每秒 20 次。别在这里做重活，也别在这里 `new` 东西。要计时就自己攒数：`if (server.getTickCount() % 20 != 0) return;`

### 实体受伤

```java
// ALLOW_DAMAGE 的返回值是「允不允许这次伤害」
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.ALLOW_DAMAGE.register(
        (entity, source, amount) -> !(entity instanceof net.minecraft.server.level.ServerPlayer
                && source.is(net.minecraft.tags.DamageTypeTags.IS_FALL)));
```

上面这段就是「玩家免疫摔落伤害」的完整实现。

### 受伤之后

```java
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.AFTER_DAMAGE.register(
        (entity, source, base, taken, blocked) -> {
            if (!(entity instanceof net.minecraft.server.level.ServerPlayer player)) return;
            // 按 taken 回血、加 buff、记仇……
        });
```

### 实体死亡

```java
net.fabricmc.fabric.api.entity.event.v1.ServerLivingEntityEvents.AFTER_DEATH.register(
        (entity, source) -> {
            if (source.getEntity() instanceof net.minecraft.server.level.ServerPlayer killer) {
                // 击杀者奖励
            }
        });
```

### 右键物品 / 右键方块

```java
net.fabricmc.fabric.api.event.player.UseItemCallback.EVENT.register((player, world, hand) -> {
    if (world.isClientSide()) return net.minecraft.world.InteractionResult.PASS;
    // 处理完返回 SUCCESS，不处理返回 PASS
    return net.minecraft.world.InteractionResult.PASS;
});
```

### 玩家加入

```java
net.fabricmc.fabric.api.networking.v1.ServerPlayConnectionEvents.JOIN.register(
        (handler, sender, server) -> {
            net.minecraft.server.level.ServerPlayer player = handler.getPlayer();
        });
```

## 一个完整例子：拿在手上就回血

钩子锚点选 `init`：

```java
net.fabricmc.fabric.api.event.lifecycle.v1.ServerTickEvents.END_SERVER_TICK.register(server -> {
    if (server.getTickCount() % 40 != 0) return;   // 每 2 秒一次
    for (net.minecraft.server.level.ServerPlayer player : server.getPlayerList().getPlayers()) {
        var held = player.getMainHandItem();
        if (held.isEmpty()) continue;
        var key = net.minecraft.core.registries.BuiltInRegistries.ITEM.getKey(held.getItem());
        if (!id("ruby_sword").equals(key)) continue;
        if (player.getHealth() >= player.getMaxHealth()) continue;
        player.heal(1.0F);
    }
});
```

要点：
- `id("...")` 是主类里的辅助方法，钩子里能直接调（因为已经在主类的类体里）。
- `getKey()` 返回 `Identifier`，和自己 `id()` 出来的比。不要拿 `Item` 对象比 —— 两边的实例来源不一定一样。
- 判 `isEmpty()` 再取值，别假设手上一定有东西。

## Mixin：改原版本身

只有「原版没提供事件」时才需要。比如「箭矢命中后不掉落」「熔炉烧得更快」这类。

配置在 `src/main/resources/<id>.mixins.json`：

```json
{
  "required": true,
  "package": "com.example.mymod.mixin",
  "compatibilityLevel": "JAVA_25",
  "mixins": ["AbstractArrowMixin"],
  "client": [],
  "injectors": { "defaultRequire": 1 }
}
```

> `compatibilityLevel` 必须填 `JAVA_25`（26.3 的 Java 级别）。`refmap` 字段**不要写** —— 新 loom 不再生成它。

一个最小的注入：

```java
package com.example.mymod.mixin;

import net.minecraft.world.entity.projectile.AbstractArrow;
import org.spongepowered.asm.mixin.Mixin;
import org.spongepowered.asm.mixin.injection.At;
import org.spongepowered.asm.mixin.injection.Inject;
import org.spongepowered.asm.mixin.injection.callback.CallbackInfo;

@Mixin(AbstractArrow.class)
public abstract class AbstractArrowMixin {
    @Inject(method = "tick", at = @At("HEAD"))
    private void onTick(CallbackInfo ci) {
        // 每 tick 都会被调用
    }
}
```

**注入点没命中 = 启动就崩**（`defaultRequire: 1`）。崩了先看两件事：方法名对不对（26.3 用官方名，不是 Yarn 名）、目标类在不在当前端。

调试时启动参数加 `-Dmixin.debug.verbose=true`，日志里能看到每个注入点匹配到没有。

## 常见卡点

**钩子加进去了但没生效**
锚点选错文件了。`init` 只插主类，`items` 只插 `ModItems.java`。改完要点「生成」。

**编译报「找不到符号」但类明明存在**
九成是没写全限定名。钩子代码没有 import。

**Mixin 启动崩溃 `InjectionError`**
`method` 名字错，或者签名对不上。重载方法要用完整描述符（`method = "tick()V"`）。

**事件注册了但服务端不触发**
在客户端侧注册了。事件注册一律放 `init` 锚点（服务端也会跑 `onInitialize`）。
