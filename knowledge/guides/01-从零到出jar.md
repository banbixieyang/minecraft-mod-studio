# 从零到出 jar

这一篇只讲一件事：**让一个 jar 出现在 `build/libs/` 里**。内容先做最简单的，后面几篇再补。

## 1. 建工程

首页点「新建工程」，填三个东西：

| 字段 | 填什么 | 注意 |
|---|---|---|
| 中文名 | 随便，会显示在界面上 | 例如 `红宝石工坊` |
| 工程 id | `lower_snake_case` | 例如 `rubyworks`，这就是命名空间，物品会变成 `rubyworks:xxx` |
| 包名 | 反向域名 | 例如 `com.example.rubyworks` |

工程 id 一旦定下来就别改 —— 所有资源路径都挂在它下面，改了等于所有东西重新注册一遍。

## 2. 加第一件东西

左侧切到「物品」，点「添加」。最少填两个：**id**（`ruby`）和**中文名**（`红宝石`）。

类型选「材料」，其它都不用管。这时点「生成」，工程里会多出这些东西：

```
src/main/java/<包名>/registry/ModItems.java         ← 注册代码（生成，别手改）
src/main/resources/assets/<id>/items/ruby.json       ← 物品定义
src/main/resources/assets/<id>/models/item/ruby.json ← 模型
src/main/resources/assets/<id>/textures/item/ruby.png← 贴图
src/main/resources/assets/<id>/lang/zh_cn.json       ← 中文名
```

贴图默认是按 id 猜色自动生成的 16×16，能看，但建议后面自己换掉（见「贴图从哪来」）。

## 3. 校验

点顶栏「校验」。它会一次性列出所有问题：id 重复、引用了不存在的材质、配方空格不合法、贴图尺寸不对。

**这一步不要跳。** 生成阶段发现的问题往往只报「冲突」，说不清是哪条内容引起的；校验会直接指名。

## 4. 生成

点「生成」。它把表单里的内容写成 Java + JSON + PNG，同时算一遍文件指纹：

- **没变过的文件不动** —— 所以你手改过的东西不会被覆盖（除了 `registry/` 下面的生成文件）。
- 生成文件头上都有 `本文件由 MC Studio 生成` 的注释。看到这行就说明改了也会被下次生成盖掉。
- 手写区是 `src/main/java/<包名>/custom/CustomContent.java`，这个文件编辑器**永远不覆盖**。

## 5. 构建 jar

点「构建 jar」，日志会实时滚。第一次很慢（要下 Gradle 发行包和平台依赖），几分钟正常。

成功后会告诉你 jar 在哪：

```
build/libs/<工程id>-0.1.0.jar
```

点「部署到 mods」可以直接复制到游戏目录，或者自己拷过去。

## 6. 进游戏验证

启动游戏，看两个地方：

1. **日志里有没有你的 mod 加载行**。没有就是 `fabric.mod.json` 或主类的问题。
2. **创造模式物品栏里能不能搜到**。搜不到但日志正常，多半是没加到创造栏（「物品」标签里勾「加入创造栏」）。

物品显示成紫黑方块 = 模型/贴图缺失，注册是好的。
物品显示成问号 = 语言文件没对应上。

## 到这里你手上有什么

一个能启动、能拿到物品、能丢给朋友的空壳 mod。接下来按顺序看：

- [物品与方块](#) —— 工具、盔甲、矿石这些有行为的
- [配方、掉落与生成]() —— 让它能合成、能挖、能在地下找到

## 常见卡点

**「构建失败：找不到 Java」**
编辑器顶栏会显示检测到的 Java。26.3 需要 **JDK 25**。装了多个版本的话，设 `JAVA_HOME` 指向 25。

**「BUILD SUCCESSFUL 但 mods 里没有」**
看 `build/libs/` 下是不是有 `-sources.jar`。那个不是给游戏用的，要的是没有后缀的那个。

**改了代码但游戏里没变化**
生成 ≠ 构建。改完表单要点「生成」，再点「构建 jar」，再重启游戏。
