# 配方、掉落与矿物生成

前三件事做完，你的 mod 才算「能玩」：东西拿得到、挖得出来、找得着。

## 配方

「配方」标签，先选**模式**：

| 模式 | 字段 | 例子 |
|---|---|---|
| 有序 `shaped` | `grid` 3×3 网格 | 剑、镐、盔甲这类有形状的 |
| 无序 `shapeless` | `ingredients` 材料列表 | 搅拌类，摆哪都行 |
| 熔炉 `smelting` | `ingredient` + `experience` + `cookingTime` | 烧矿石出锭 |
| 高炉 `blasting` | 同上，时间默认一半 | 矿石专用，快 |
| 烟熏 `smoking` | 同上，时间更短 | 食物专用 |
| 营火 `campfire` | 同上 | 不用燃料的慢烤 |
| 切石机 `stonecutting` | `ingredient` + `result` + `count` | 石头切方块 |
| 锻造台 `smithing` | `base` + `addition`（+ 可选 `template`） | 升级已有装备，如钻石剑 → 红宝石剑 |

**锻造台怎么填**：`base` 是要改造的东西（`minecraft:diamond_sword`），`addition` 是升级材料
（`fallen:ruby`），`template` 是锻造模板 —— 原版 1.20 之后大多数升级都要模板，留空就不生成这个字段。
产出照常填 `result`。1.20.1 生成的是 `{item, count}`，26.x 是 `{id, count}`，不用你操心。

表单会**按模式只显示相关字段**：选锻造台时网格、材料清单、经验这些都会藏起来，
不会让你对着一堆无关输入框猜哪个有用。

**有序配方怎么填网格**：直接在 3×3 里点格子，每次点会问你要放哪个物品。填进去的 id 必须是完整 id（`ruby` 或 `minecraft:stick`）。

空着的格子保持空 —— 网格是 9 格全量存的，空格就是空格，不会被压缩。

**材料写 `ruby` 还是 `rubyworks:ruby`？**
自己工程的东西写短名就行，编辑器会自动补命名空间。原版物品必须写 `minecraft:` 前缀，否则会被当成你自己命名空间下的 `minecraft` 物品。

## 掉落

掉落是**方块**的字段，不是物品的。在「方块」标签里找到 `drops`。

每条掉落填四样：

| 字段 | 说明 |
|---|---|
| 物品 | 掉什么。填 `self` 表示掉方块自己 |
| 数量 | 最少~最多，或固定值 |
| 概率 | 0~1。不填就是 100% |
| 吃时运 | 勾上后时运附魔会按原版公式加数量 |

**最容易踩的坑**：`drops` 空了就是「挖了什么都不掉」，不会默认掉自己。所有方块都要显式配一条。

矿石的典型配法：掉 1 个材料物品，吃时运，旁边再配一条「精准采集时掉方块自己」。后者编辑器会帮你一起生成（勾「精准采集保留方块」）。

## 矿物生成

「矿物生成」标签的字段：

| 字段 | 含义 | 典型值 |
|---|---|---|
| `dimension` 维度 | 主世界 / 下界 / 末地 | 主世界 |
| `overworldBlock` | 主世界生成什么方块 | 你的矿石 |
| `deepslateBlock` | 深板岩层生成什么 | 深板岩版本矿石 |
| `size` 矿脉大小 | 一簇最多几个方块 | 见下面警告 |
| `count` 每区块尝试次数 | 越大越密 | 4~10 |
| `rarity` 稀有度 | 越小越稀有（约等于「多少区块里出一个」） | 2~8 |
| `minY` / `maxY` | 生成高度范围 | -64 ~ 64 |
| `discardChance` | 碰到空气就放弃的概率 | 0 |

> **尺寸陷阱：`size` 填小于 4，游戏里一个方块都不会生成。**
> 这不是 bug，是 26.3 的生成器在矿脉太小时会直接跳过。表单已经做了下限，但你手改 json 时要注意。

主世界会自动分两层：石头层用 `overworldBlock`，深板岩层（Y < 0）用 `deepslateBlock`。两个都填上，矿才会从地表一直分布到地底。

下界和末地没有深板岩层，只填 `block` 一个就行。

生成的文件在：

```
data/<id>/worldgen/configured_feature/<name>.json
data/<id>/worldgen/placed_feature/<name>.json
```

`configured_feature` 描述「长什么样」，`placed_feature` 描述「长在哪、多密」。这两个必须成对存在，少一个矿就不会生成。

## 进度（可选）

「进度」标签能加成就。最容易踩的坑：

**可见的根进度必须有背景图**，否则服务端直接拒绝加载整个数据包，报 `Visible advancement roots must have background`。

编辑器在根进度上会强制你填，非根进度不用。

## 走一遍完整流程

做一个「红宝石」主题的最小可玩内容：

1. 物品：`ruby`（材料）
2. 物品：`ruby_sword`（工具/剑，材质用原版钻石先跑通）
3. 方块：`ruby_ore`（矿石，掉落 → `ruby` ×1，吃时运，经验 1~3）
4. 配方：`ruby_sword`，有序，钻石剑的形状，材料全换 `ruby`
5. 矿物生成：主世界，`ruby_ore` / 深板岩版，size 6，count 4，Y -64~48

校验 → 生成 → 构建。进游戏 `/give @s rubyworks:ruby_sword`，再到地下找矿。

## 常见卡点

**配方合不出来，但材料都对**
有序配方的形状必须和网格完全一致。剑是「两竖一横」，不是「一横两竖」—— 对着网格再核一遍。

**矿石只在创造模式拿得到，生存挖不到**
`requiresTool` 勾了但没给正确工具，或者掉落表空了。

**`/locate` 找不到结构、矿也刷不出来**
`placed_feature` 没生成 —— 通常是 `size` 太小或者 `rarity` 填成了 0。
