# 套装效果（穿齐四件才生效）

**目标**：四件 `ruby_` 盔甲全穿上时获得「急迫 I」，脱掉任意一件就消失。

## 前置

- 四个盔甲条目，id 带同一个前缀（例如 `ruby_helmet` / `ruby_chestplate` / `ruby_leggings` / `ruby_boots`）
- 只要 id 前缀一致，具体叫什么不影响这段代码

## 代码

锚点选 `init`：

```java
net.fabricmc.fabric.api.event.lifecycle.v1.ServerTickEvents.END_SERVER_TICK.register(server -> {
    // 每 40 tick（2 秒）检查一次。装备变化不会那么频繁，
    // 而且每 tick 遍历所有玩家，人一多就白烧 CPU
    if (server.getTickCount() % 40 != 0) {
        return;
    }
    var slots = new net.minecraft.world.entity.EquipmentSlot[]{
            net.minecraft.world.entity.EquipmentSlot.HEAD,
            net.minecraft.world.entity.EquipmentSlot.CHEST,
            net.minecraft.world.entity.EquipmentSlot.LEGS,
            net.minecraft.world.entity.EquipmentSlot.FEET};
    for (net.minecraft.server.level.ServerPlayer p : server.getPlayerList().getPlayers()) {
        int worn = 0;
        for (var slot : slots) {
            var stack = p.getItemBySlot(slot);
            if (stack.isEmpty()) {
                continue;
            }
            var key = net.minecraft.core.registries.BuiltInRegistries.ITEM.getKey(stack.getItem());
            if (key.getPath().startsWith("ruby_")) {
                worn++;
            }
        }
        if (worn == 4) {
            p.addEffect(new net.minecraft.world.effect.MobEffectInstance(
                    net.minecraft.world.effect.MobEffects.HASTE,       // 急迫（26.3 字段叫 HASTE，不叫 DIG_SPEED）
                    100,                                               // 5 秒，比检查间隔长，接得上
                    0,                                                 // I 级
                    true,                                              // 粒子少（环境效果）
                    true));                                            // 显示图标
        }
    }
});
```

## 为什么这么写

**按部位查，不查背包。** 直觉写法是遍历背包看有没有这四件，但那样玩家把它们塞进箱子也能触发。`getItemBySlot(EquipmentSlot.HEAD)` 看的就是「身上穿着什么」，这才是套装该有的语义。

**用 id 前缀而不是四个 equals。** `key.getPath().startsWith("ruby_")` 只认前缀，所以你加第五件 `ruby_` 装备时这段代码不用改。想严格限定四件就把前缀判断换成四个 `key.equals(id("ruby_helmet")) || ...`。

**效果时长要比检查间隔长。** 这里 100 tick 的效果 + 40 tick 的检查间隔：即使某次检查被跳过，效果也不会断。反过来（效果 20 tick、检查 40 tick）会一闪烁一闪。

**脱掉就消失是自动的。** `addEffect` 每次刷新时长，一旦 `worn != 4` 就不再刷新，剩余时间走完效果自然没了 —— 不需要写「移除效果」的代码。想立刻移除可以加 `else { p.removeEffect(...); }`，但通常不必。

## 变体

**每件给一点，穿齐再额外加：**

```java
if (worn >= 1) { p.addEffect(new net.minecraft.world.effect.MobEffectInstance(
        net.minecraft.world.effect.MobEffects.SPEED, 100, 0, true, true)); }       // 速度
if (worn == 4) { p.addEffect(new net.minecraft.world.effect.MobEffectInstance(
        net.minecraft.world.effect.MobEffects.STRENGTH, 100, 1, true, true)); }    // 力量
```

**穿齐时给抗性（减伤），但只在受伤后判定**：把这段挪到 `ServerLivingEntityEvents.ALLOW_DAMAGE` 里，
判断 `entity` 是不是玩家、四件是否齐全，再决定是否取消伤害。注意那是**事件**，每次受伤都会调，
不能再按 tick 取模。

**只对某一套生效**：把 `startsWith("ruby_")` 换成 `key.equals(id("ruby_helmet")) || key.equals(id("ruby_chestplate")) || key.equals(id("ruby_leggings")) || key.equals(id("ruby_boots"))`。

## 常见坑

- `BuiltInRegistries.ITEM.getKey(item)` 返回的是 `Identifier`，拿 `equals` 比，别拿 `==`。
- `getItemBySlot` 对空槽返回 `ItemStack.EMPTY`，先 `isEmpty()` 再取 `getItem()`。
- 别用 `p.getInventory().armor` 之类按索引取 —— 索引顺序在不同版本变过，`EquipmentSlot` 不会。
- **效果字段名用经典名**：26.3 的 `MobEffects` 里是 `HASTE`（急迫）/ `SPEED`（速度）/ `STRENGTH`（力量）/ `SLOWNESS`（缓慢）/ `REGENERATION`（生命恢复）。老教程里的 `DIG_SPEED`、`MOVEMENT_SPEED`、`DAMAGE_BOOST`、`MOVEMENT_SLOWDOWN` 在 26.3 **都不存在**，写了直接「找不到符号」。拿不准就 `javap -classpath <minecraft-merged.jar> net.minecraft.world.effect.MobEffects` 查一遍；速查里的《26.3 踩坑清单》也列了这条。
