① 扩展系统怎么工作

一个扩展 = 一个文件夹 + 一个 index.mjs，引擎启动时自动装载 
// core/analyze/ext/<扩展名>/index.mjs
export default {
  id: 'goety-revelation',
  name: 'Goety: Revelation 扩展',

  // 只对命中的 jar 激活，别的包不受影响
  match: (meta) => meta.id === 'goety_revelation',

  // 新增「内容类型」→ 拆解台左侧多出分组
  contentTypes: {
    focus:   { label: '聚晶' },
    setBonus:{ label: '套装词条' },
  },

  // 拆解台里可编辑的字段
  fields: {
    focus: [{ key: 'level', label: '等级', kind: 'int', min: 1 }],
  },

  // 真正的解析：读 jar 资源，产出内容条目
  analyze(ctx) {
    return { contents: { focus: [...] }, warnings: [...] };
  },
};
装载流程
  • 引擎模块加载时扫描 core/analyze/ext/*/index.mjs，一次性装好（等价于 MC 启动时加载全部 mod）。
  • analyze() 时只跑 match() 命中的扩展——别的包不加载它，也就零开销零污染。
  • 扩展往报告的 contents 里塞新内容类型，并声明这些类型在拆解台的可编辑字段。
  • 导出时 reportToPack 照旧按 id 合并数值，新类型自动进包（后端格式没变）。

新增一种 mod 的支持 =
  • 拖一个文件夹进 core/analyze/ext/，写好 index.mjs，核心代码零改动。
  • 引擎重启即生效（无需改注册表、无需改 UI）。

④ 怎么用

在 MC Studio 界面里走一遍
  1. 打开 MC Studio → 顶栏「分析」→「管理已导入…」
  2. 找到 GoetyRevelation-2.3.3fix，点 拆解 → 进入拆解台
  3. 左侧分组会出现 仪式/熔炉配方 聚晶 套装词条 三个新分组
  4. 在卡片里直接改数值（例如把聚晶等级 1 → 8、把仪式配方产物数量调高）
  5. 点 导出为包（存库） → 存进包库；勾了「存库并应用」则同时应用到当前工程
